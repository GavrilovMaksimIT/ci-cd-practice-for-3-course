# Отчёт по практической работе CI/CD

## Выполненная подготовка

Проект из `demo` перенесён в корень репозитория: `site/`, `tests/` и `build.py`. Workflow находится в `.github/workflows/ci.yml` и соответствует содержимому `workflow_templates/ci.yml.txt`.

Финальное состояние страницы восстановлено после проверки поломки: используется `href="style.css"`, а номер аудитории изменён на `302`.

## Поломка stylesheet

Если заменить только `href="style.css"` на `href="missing.css"`, упадёт тест `test_stylesheet_exists`. Причина из журнала: `Missing stylesheet: missing.css`.

После неуспешного шага `Run tests` GitHub Actions останавливает последующие шаги job: `Build site` и `Save site artifact` не выполняются, поэтому артефакт `lesson-site` для красного запуска не создаётся.

## Runner и артефакт

Тесты выполняются на GitHub-hosted runner `ubuntu-latest`, а не только на локальном компьютере. Шаг `Save site artifact` загружает каталог `dist/` в GitHub Actions. Файл `release.json` сохраняет значение `GITHUB_SHA` исходников. Скачивание артефакта само по себе не публикует сайт в интернете.

Workflow настроен на каждый `push` в ветку `main`. Поэтому отдельный коммит с `report.md` также создаёт новый запуск. Запуски нужно сопоставлять с конкретными коммитами или их SHA, а не только с положением в списке: между ними могут появиться другие изменения и проверки.

## Изменение аудитории

После изменения `Аудитория: 301` на `Аудитория: 302` перечисленные тесты остаются зелёными. Они проверяют заголовок, h1, stylesheet и тему занятия, но не проверяют правильность номера аудитории. Поэтому зелёный результат доказывает только прохождение этих конкретных проверок.
